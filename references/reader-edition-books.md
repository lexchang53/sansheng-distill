# 完整读者版：一套正文与有限轮次

适用：用户明确接受降低细粒度保留/审计要求，以提高整书交付效率。普通书仍按 high-retention-books.md §0 定档；本档不自动替代严格深读档，也不用于视频、企业现状、人物事实库或医疗法律金融指导。用户指定档位优先于“核心经典自动严格深读”。项目对本批的授权不等于所有任务的默认授权。

本文件只定义读者档的流程和证据范围。模型车道、成本统计、失败收口复用 book-batch-operations.md；管理类额外外查豁免必须有独立授权，不由本档自动推导。科学内容外部核验仍按 enrich.md，不继承管理书免外查规则。

## 1. 起点与单一正文

开工记录 quality_profile=reader、授权的质量取舍、必留范围、核心研究范围、允许调用/时间预算和已有成果。保留主论证、定义、关键案例、反例、条件与实质附录；可省次要例子、纯出处尾注和细微重复。没有逐项覆盖测量就不声明高保留百分比或使用严格深读数据绿灯。

正文只设一个权威字段集合。新书优先以 chapters[].narrative 为权威正文，速览/核心卡片/规则/行动清单从已审正文提取。不要另写同规模的“理解层”。旧书已有 deepread 单元时复用，并在装配清单声明权威文本及投影关系；确需第二视图时由权威正文分组/抽取，不重新生成近似长文。下游尚不能消费同源派生时先做最小适配，不伪造现有结构。

保持原书章与阅读部分身份、来源段定位和图意。批量任务按论证边界及真实模型长度切片，不按固定知识条数切成大量微任务。必要图表须实看和讲清机制；不为赶预算忽略改变结论的图或表。

## 2. 六步及停止条件

| 步骤 | 完成证据 | 允许进入下一步的条件 |
|---|---|---|
| 来源预检 | 版次/原件与文本SHA、有效章及实质附录、异常与图表裁决 | 无未解决关键缺源；未变来源复用旧审据 |
| 一次正文生产 | 连续正文、章节要点/案例/反例/限制、原书定位及待核验项 | 必留章节与主论证齐备；源短不加戏，源长不静默截断 |
| 一轮审核 | 当前正文绑定的问题清单；事实忠实与重要遗漏分别有结果 | 检查覆盖各章节组；主控核全部报警和高风险项及分层抽样 |
| 定点修正与研究 | 变更差异、受影响来源复验、声明核心研究的逐项裁决 | 实质错误清零；经验结论未核验不得冒充已支持 |
| 同源装配 | 正文版本、派生卡片与页面、整包迁移及索引差异 | 无旧锚点/附属数据混用；他书贡献未误改 |
| 消费者验收 | 当前输入的页面/入口与必要发布收据 | 通过实际消费者；已授权网站发布还须真实成功和公网新版 |

默认一次生成、一次有效审核、一次定点修正。修正后只复核变化及其依赖，不重发全书。再开一轮必须记录触发问题、影响范围和新的停止条件；不能仅因模型建议“进一步完善”无限循环。实质事实错误、核心遗漏、否定/因果/公式条件错误阻断；普通措辞、次要例子缺失记发布后改进。

审核模型读取对应来源与当前正文，各章节组均有事实和要点检查结果；主控核问题清单、高风险数字/引文/主体/因果及约10%章节组的确定性抽样（至少一组，小书一组则全取）。抽样出现实质错误，扩查同类错误或来源组；跨章普遍错误再扩大至全书。记录抽样对象、发现和扩查理由，不把未抽样部分写成主控逐句核过。

## 3. 科学范围与旧状态

核心观点/行动规则的研究范围由重要性决定，可先选约5–8个经验结论，但不是硬上限。所有对外科学证据卡仍遵守 enrich.md 的完整字段、claim_id对应和终审契约。不能把本来重要的行动结论移出核心，只为少做核验。

未进入研究范围的非核心经验描述可作为明确归属的原书记载保留，注明未独立核验；不为其捏造证据卡，不将“没有查”写为not_supported或not_testable。框架/数学/规范建议按性质裁决，不套经验验证标签。原书来源忠实与当前科学正确分开签署；科学收据只签实际核过的对象。旧书重蒸取消/改写的claim按语义登记保留、合并、替换或退出卡片，并核读者页没有隐藏重要结论。既有消费者如要求更大的研究范围，先真实完成或正式适配，不能仅改范围字段把旧硬门禁变绿。

## 4. 预算与交付

项目设置阶段时间与token预算；未设置时先用一本实际新书测量，不把某项目的100万token、模型/并发或100–160分钟写成通用能力保证。预算接近耗尽时停止非必要扩批，优先复用、定点修正和装配；超预算有必要缺口则记录理由，预算耗尽不能标完成，也不自动请求新增权限。

计时与用量按 book-batch-operations.md §5；至少记录输入/输出版本、阶段开始结束、调用数、去重已知token、未知usage、返工理由、排队及交付状态。没有记录标未知，不补造历史数字。

strict与reader分别报告。reader完整性依据章节主论证/案例/反例/限制清单及审核结果，不调用book_coverage.py后把其严格逐项覆盖状态改为true；已有严格证据可以复用，但如实保留其原档位。页面与发布门禁仍保留。若工具只接受旧严格输入，新增显式档位与反例后再用，不假造签署、不跳门。检查器通过只证明它实际覆盖的契约，不能代替阅读或上线。
